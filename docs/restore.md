# Restoring Nabu on a fresh box

Everything derived is rebuildable; everything permanent lives in the
permanent folders. This page is the whole restore doctrine.

## What is permanent — the three-folder contract (P71)

- **`canonical/`** — the universal library asset: every fetched
  source and every module's reference data (the attic included).
- **`config/`** — the git-shared project definition: the registries'
  rules and overrides, facet rules, postures, alignments.
- **`local/`** — THE INSTANCE: the owner shelves
  (`local/shelves/` — source/language/place dossiers, the acquired
  library, notes), the instance config (`local/config/` — per-document
  lect rulings, grant agreements, creep acceptances, link scopes, the
  box profile, the settings overlay), and the operational ledger
  (`local/history.sqlite3` — run history, pins, license baselines,
  revisions). Never in the public repo.

That is the WHOLE contract. Everything under `db/` is a pure function
of those three folders, regenerated by `nabu rebuild` — the catalog,
the fulltext/derived indexes, the lect journal (re-derived from the
rulings + rules + date inference), the links instrument.

One non-contract extra rides in `nabu backup` by default: **`.docs/`**
— the steering record (decision register, plan docs, surveys; №R-22,
owner-ruled 2026-08-11). It is owner input the rebuild can never
regenerate, but it is working material, not part of the three-folder
contract — a fresh box works without it.

A same-named overlay file under `local/config/` merges over its
`config/` counterpart (lect_overrides, lect_facet_rules, postures —
your instance's refinements win without forking the project files).

Outside the contract, named: files sitting in `incoming/<slug>/` that
you have not yet ingested (re-acquire them by hand — each manual-drop
registration prints its acquisition card at sync). The repo itself (code,
docs, site) is backed by its git remote. A pre-P71 box whose files
still sit at the legacy locations (rulings in config/, shelves under
canonical/, the ledger under db/) keeps working — every read warns
until `nabu migrate-local` moves them home, and `nabu backup` REFUSES
outright while the ledger still sits at `db/history.sqlite3` (a
snapshot that missed the run history would be a silently incomplete
backup).

## Path 1 — carry the assets (minutes)

1. Clone the repo, `bundle install`.
2. Copy `canonical/`, `config/`, and `local/` from the old box (or
   from backup) — and `.docs/` if you keep the steering record, which
   the backup carries by default.
3. `bin/nabu rebuild` — one command re-derives the catalog, the
   fulltext index, and every derived lane (timeline, facets, place
   index and apply, char postings, the lect journal, links). Done.

## Path 2 — fresh from upstreams

1. Clone, `bundle install`, **`bin/nabu quickstart`** — the CORE group
   syncs automatically, pre-enabled: nabu-lects · nabu-places · cigs,
   the registry instruments, whose `requires:` closure rides in
   pleiades and trismegistos-geo — five instruments in all.
   Trismegistos-geo is a manual drop, so on a fresh box the sweep
   prints its acquisition card (see the Manual-drop paragraph below);
   the starter shelf follows.
2. **Capability groups** — a group name expands for both commands:
   - `bin/nabu enable signs && bin/nabu sync signs` restores the whole
     sign/character capability: the three modules (osl, unikemet —
     the identity spines — and edubba-overlay, the didactic layer;
     machinery, no enablement) plus the Han card's shelves,
     the reading lanes, and the Wiktionary sense lane.
3. **Everything else is enable-then-sync per source or per axis**
   (`nabu enable germanic && nabu sync germanic`). Grant-gated sources
   additionally need their grant recorded (the sync explains).
4. Corpus-scale attestation panels (the char cards' corpus lines, the
   place desk's holdings) count whatever is held — sync the corpora
   you care about, in any order.

Manual-drop registrations (trismegistos-geo — a `kind: module` row —
and any registration whose upstream only a human can download) print
their acquisition instruction card at sync until you drop the file in
`incoming/<slug>/` — nothing fails, nothing is skipped silently.

One ordering note: run `bin/nabu rebuild` before the FIRST sync of a
source whose fetch reads the links instrument (trismegistos computes
its fetch cone from reference edges) — the rebuild re-mints the links
db those fetches consult.

## The one rule that makes order irrelevant

Every desk degrades **section by section, honestly**: an unsynced
shelf is an absent section, an unbuilt index is a "not indexed yet"
hint, an unheld gazetteer is a sync note — never an error, never a
placeholder. There is no wrong sequence; there is only more or less of
the library present.
