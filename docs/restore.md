# Restoring Nabu on a fresh box

Everything derived is rebuildable; everything permanent lives in the
permanent folders. This page is the whole restore doctrine.

> **Ruled 2026-08-11 (lands as its own phase):** the permanent set
> becomes THREE folders — `canonical/` (the universal library asset),
> `config/` (the git-shared project definition), and **`local/`** (the
> local instance: owner shelves and rulings, grants, the operational
> ledger, acquisitions). Until that elevation lands, the interim
> two-folder state below is the operational truth.

## What is permanent — the two-folder contract (P70, interim)

- **`canonical/`** — the library's asset: every fetched source, every
  module's reference data, and the owner-authored shelves
  (local-source/local-language/local-place dossiers, notes — ruled to
  elevate into `local/`).
- **`config/`** — every decision: the registries' rules and overrides,
  per-document lect rulings (`lect_rulings.yml`), grant agreements
  (`grants.yml`), creep acceptances, postures, the box profile (the
  instance-specific files among these are ruled to move to `local/`).

That is the WHOLE backup. Everything under `db/` is a pure function
of those two folders, regenerated by `nabu rebuild` — the catalog,
the fulltext/derived indexes, the lect journal (re-derived from
config rulings + rules + date inference), the links instrument.

The one interim exception: the operational LOG (`db/history.sqlite3`)
is outside the two-folder set, so a `--skip-derived` restore loses it.
Named honestly, that loss is: the revision history (every document's
past content states) and the sync-run log; license-drift detection
silently re-baselines at the first probe after restore; quarantine-
creep detection restarts its low-water anchors from current levels.
`nabu backup` copies the ledger by default, so in practice the history
survives — and under the 2026-08-11 ruling its home moves to `local/`
(part of the permanent set), which closes this loss window entirely
when the elevation phase lands.

Also outside the contract: files sitting in `incoming/<slug>/` that
you have not yet ingested (re-acquire them by hand — each Manual
source prints its acquisition card at sync).

## Path 1 — carry the assets (minutes)

1. Clone the repo, `bundle install`.
2. Copy `canonical/` and `config/` from the old box (or from backup).
3. `bin/nabu rebuild` — one command re-derives the catalog, the
   fulltext index, and every derived lane (timeline, facets, place
   index and apply, char postings). Done.

## Path 2 — fresh from upstreams

1. Clone, `bundle install`, **`bin/nabu quickstart`** — the CORE group
   (nabu-lects · nabu-places · cigs, the registry instruments) syncs
   automatically, pre-enabled; the starter shelf follows.
2. **Capability groups** — a group name expands for both commands:
   - `bin/nabu enable signs && bin/nabu sync signs` restores the whole
     sign/character capability: the two identity-spine modules (osl,
     unikemet — machinery, no enablement) plus the Han card's shelves,
     the reading lanes, and the Wiktionary sense lane.
3. **Everything else is enable-then-sync per source or per axis**
   (`nabu enable germanic && nabu sync germanic`). Grant-gated sources
   additionally need their grant recorded (the sync explains).
4. Corpus-scale attestation panels (the char cards' corpus lines, the
   place desk's holdings) count whatever is held — sync the corpora
   you care about, in any order.

Manual-Adapter sources (trismegistos-geo, and any source whose
upstream only a human can download) print their acquisition
instruction card at sync until you drop the file in `incoming/<slug>/`
— nothing fails, nothing is skipped silently.

## The one rule that makes order irrelevant

Every desk degrades **section by section, honestly**: an unsynced
shelf is an absent section, an unbuilt index is a "not indexed yet"
hint, an unheld gazetteer is a sync note — never an error, never a
placeholder. There is no wrong sequence; there is only more or less of
the library present.
